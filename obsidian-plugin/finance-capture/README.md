# Finance Capture для Obsidian

Минимальный мобильный плагин, который сохраняет операции в Syncthing-папку внутри хранилища. Плагин не использует Node.js API и рассчитан на Obsidian Mobile.

## Обновление 0.10.7

Суммы в форме автоматически разделяются точками по тысячам; дробная часть вводится через запятую.

## Установка для тестирования

1. Скопируйте папку `finance-capture` в `<ваше хранилище>/.obsidian/plugins/`.
2. Перезапустите Obsidian.
3. Включите `Finance Capture` в разделе Community plugins.
4. В настройках плагина задайте автора и папку, например `Finance Sync`.
5. Настройте Syncthing так, чтобы `Finance Sync` на телефоне синхронизировалась с папкой `mobile-sync` этого проекта на компьютере.

## Синхронизация справочников

Desktop-приложение публикует валюты, категории с эмодзи, типы необходимости, типы операций и активные счета из Excel в `config/lists.json`. Syncthing доставляет файл на телефон, после чего Finance Capture использует эти значения во всех новых формах.

Полный цикл запускается при старте desktop-приложения, появлении готового JSON и каждые пять секунд как страховка. Кнопка «Обновить данные Obsidian» в настройках desktop запускает тот же цикл: импорт, подтверждение, удаление обработанной очереди и публикацию справочников с итоговым балансом. Файл перезаписывается только при реальном изменении справочников. При изменении синхронизированного файла уже открытые панели перечитывают список счетов автоматически. Если файл отсутствует или повреждён, плагин использует встроенные резервные справочники, но не позволяет сохранить новую операцию без синхронизированного счёта.

## Панель общих балансов

Desktop-приложение публикует обычные активные счета в `config/balances.json`. Снимок рассчитывается по Excel: включает начальные балансы и операции по текущую дату, а будущие операции исключает. Накопительные счета и ожидающие импорта мобильные операции в него не входят.

Мобильная панель отдельно показывает по каждому обычному счёту текущий остаток, изменение по JSON-операциям из `incoming` и прогнозный остаток. Доходы и расходы меняют один счёт; перевод уменьшает исходный счёт и увеличивает счёт назначения в их собственных валютах. Импортированные операции не учитываются повторно, если снимок уже включает их; отклонённые операции исключаются. Общий итог в RUB остаётся значением из опубликованного снимка и не пересчитывается по очереди. При удалении карточки «В очереди» связанный JSON отменяется, после чего прогноз обновляется.

Чтобы вставить панель в заметку, выполните команду «Вставить панель общих балансов в заметку». Она добавит блок:

````markdown
```finance-balances
```
````

Панель показывает остаток каждого счёта в его валюте и общий итог в RUB по текущим курсам ЦБ РФ. Если курс недоступен, суммы счетов остаются видимыми, а общий итог помечается как недоступный. Открытая панель обновляется при получении нового снимка через Syncthing. Без синхронизации отображается последний полученный снимок с датой расчёта.

Доход и расход записываются на выбранный счёт. Форма использует одну заметку без отдельного описания и способа оплаты. «Перевод» требует исходный и конечный счёт; при разных валютах нужно указать фактически зачисленную сумму. Операция раньше даты начала любого затронутого счёта запрещена, а desktop-приложение подставит курс ЦБ во время импорта.

Для быстрого ввода можно по-прежнему использовать иконку кошелька или команду «Добавить финансовую операцию».

Чтобы разместить форму прямо в заметке, выполните команду «Вставить панель добавления операции в заметку». Она добавит блок:

````markdown
```finance-capture
```
````

В режиме чтения или Live Preview блок превращается в форму. Таких панелей можно создать сколько угодно — каждая новая операция всё равно попадает в общую очередь.

При сохранении сначала создаётся `.pending`, затем готовый JSON в `Finance Sync/incoming` и read-only Markdown-карточка в `Finance Sync/operations`. Подпапку карточек можно изменить в настройках плагина. Редактирование карточки не меняет JSON.

Карточки в очереди получают имена вида `1 — В очереди — 2026-10-14 — 🛒 Продукты — 420,5 RUB.md`. После импорта и синхронизации удаления JSON плагин автоматически переименует карточку в `2 — Архив — 2026-10-14 — 🛒 Продукты — 420,5 RUB.md`. Поэтому при сортировке по имени ожидающие операции находятся выше архивных. Если имя уже занято, плагин добавляет короткий уникальный суффикс. Изменение эмодзи категории в desktop-приложении также переименует связанные карточки после синхронизации нового справочника.

После успешного импорта компьютер удалит входной JSON, Syncthing очистит его на телефоне, а плагин пометит Markdown-карточку как архивную переименованием. Если удалить карточку до импорта при работающем плагине, он удалит связанный JSON после проверки пути и совпадения ID. Удаление карточки после импорта не изменяет Excel.

Если карточку удалили или переименовали при выключенном плагине, JSON остаётся в очереди. Отсутствие старого пути может означать незавершённую синхронизацию, поэтому при запуске плагин только восстанавливает связи с найденными карточками. Для явной очистки ожидающих операций используйте панель управления. Некорректные и посторонние JSON она сохраняет.

## Обновление 0.10.2

Проверяются пути и идентификаторы файлов перед удалением. Поддельная ссылка карточки не позволяет удалить обычную заметку за пределами очереди. Переименование карточки при выключенном плагине больше не отменяет ожидающую операцию. Обновите `main.js` и `manifest.json` на устройствах и перезагрузите плагин.

Команда «Статус синхронизации» показывает число операций, которые ещё ожидают импорта, и полученных квитанций.

## Панель управления записями

Команда «Вставить панель управления мобильными операциями» добавляет в заметку блок:

````markdown
```finance-capture-manager
```
````

Панель содержит две команды с обязательным подтверждением:

- «Удалить архивные записи» удаляет только карточки, для которых JSON уже отсутствует в `incoming`;
- «Удалить все записи» удаляет все карточки Finance Capture и все ожидающие JSON из `incoming`.

Обычные заметки, заметки с панелями, квитанции и строки, уже импортированные в Excel, не удаляются. Панель можно вставить в любое количество заметок — все экземпляры управляют одним и тем же набором файлов.
# Обновление 0.10.1

Замените `main.js`, `manifest.json`, `styles.css` в `.obsidian/plugins/finance-capture`, сохранив `data.json`, и перезапустите плагин.

Статусы карточек перепроверяются также при появлении и переименовании JSON и карточек: порядок доставки Syncthing больше не требует ожидания десятисекундной проверки. После удаления JSON проверка выполняется сразу, повторно через 500 мс и каждые 10 секунд как страховка. «Архив» означает отсутствие связанного JSON. Успех desktop-кнопки подтверждает обработку на компьютере; доставка изменений на телефон зависит от Syncthing.

Категории показывают синхронизированные эмодзи. Порядок счетов соответствует desktop. В переводах вводятся «Списано» и «Зачислено»; для одинаковой валюты второе поле серое и автоматически повторяет первое. Подтверждённая desktop-очистка через `config/reset.json` удаляет старую очередь и управляемые карточки, не затрагивая обычные заметки. Дата вводится в отдельном текстовом поле или выбирается кнопкой календаря; так Android не рисует иконку поверх даты.

## Обновление 0.10.3

Проверка календарных дат, типов и пределов сумм до создания JSON. Для записи нужен синхронизированный активный счёт. Неизвестная версия справочников не принимается; некорректный снимок не заменяет последний корректный баланс. Контракт schema 1 сохранён. Обновите main.js, manifest.json и styles.css, сохранив data.json.

## Обновление 0.10.6

Ожидаемый остаток в панели балансов выделяется зелёным при положительном значении и красным при отрицательном. Ожидаемое изменение остаётся нейтральным при любом знаке.

## Обновление 0.10.5

Панель балансов показывает текущий остаток, ожидаемое изменение и прогнозный остаток обычных счетов с учётом очереди мобильных JSON. Переводы учитываются отдельно по исходному и целевому счетам; изменение общей суммы в RUB не рассчитывается. Прогноз обновляется при появлении/удалении JSON и после удаления связанной карточки.

## Обновление 0.10.4

Закрытие capture-панели освобождает её callback. Выгрузка плагина останавливает отложенную сверку. «Архив» означает отсутствие JSON в очереди; подтверждение импорта показывается отдельно по квитанции с совпадающим ID. Поздние/частичные квитанции перепроверяются; отсутствие квитанции не считается доказательством импорта. После очистки старых квитанций статус снова может быть неподтверждённым — данные Excel от этого не меняются. Менеджер описывает очистку именно карточек без JSON.
