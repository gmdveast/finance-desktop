# Финансовый журнал

Локальное веб-приложение, которое читает и редактирует `local-data/uchet_povsednevnyh_finansov.xlsx`. Книга, настройки, резервные копии и кэш курсов хранятся в `local-data/`, исключённой из Git. Папка очереди Syncthing остаётся в `mobile-sync/` рядом с исходниками и тоже исключена из Git.

## Запуск

1. Установите [Node.js](https://nodejs.org/) версии 24.15.0 или новее в пределах ветки 24.x.
2. Один раз выполните `npm install` в этой папке.
3. Запустите `npm start` или дважды щёлкните `start-finance.bat`.
4. Откройте [http://127.0.0.1:4173](http://127.0.0.1:4173).

Пока приложение запущено, не редактируйте рабочий файл в Excel. Перед изменением приложение проверяет новую книгу, сохраняет предыдущую версию в `local-data/backups` и заменяет рабочий файл. Сервер и CLI используют общую блокировку записи. Хранятся последние 30 автоматически созданных копий по времени, включая копии перед восстановлением.

Для остановки дважды щёлкните `stop-finance.bat` или выполните `npm stop` из папки приложения. Команда ждёт завершения текущих операций и синхронизации; открытое окно сервера не требуется. Она работает с сервером, запущенным после обновления на эту версию. Для старого процесса без файла состояния будет выведено сообщение, принудительное завершение не выполняется.

Приложение создаёт резервную копию книги перед каждой записью и перед восстановлением из выбранной копии.

Курсы иностранных валют загружаются с сайта ЦБ РФ. Для выходного или праздничного дня используется опубликованный ЦБ курс, действовавший на выбранную дату. Курс можно заменить вручную.

## Счета и остатки

Во вкладке «Баланс» блок «Изменение стоимости текущего остатка» объединяет счета по валютам и оценивает **одни и те же текущие суммы** по курсам на первое число месяца и сегодня. Разница не является фактическим доходом за месяц. При недоступности курса итог не подменяется нулём.

Порядок счетов меняется перетаскиванием за маркер слева от названия (с клавиатуры — Alt+↑/↓ на маркере) и синхронизируется в Obsidian. F6 / Shift+F6 переключают фокус между боковой панелью и содержимым, сохраняя последнее выбранное поле.

Для перевода укажите «Списано» и «Зачислено». При одинаковой валюте зачисление автоматически равно списанию и недоступно для редактирования; при разных валютах обе суммы вводятся вручную. Курс перевода вводить не нужно.

В настройках «Удалить историю» удаляет операции, сохраняя счета; «Полная очистка» удаляет операции и счета. Обе команды сохраняют справочники и бэкапы, требуют ввода подтверждающей фразы и создают бэкап Excel. Они также очищают мобильную очередь и созданные плагином карточки. Обычные заметки не удаляются. Старые события, доставленные после очистки, не импортируются повторно.

Каждый новый доход или расход привязывается к счёту. Текущий остаток считается от нуля по привязанным доходам и расходам с учётом переводов между своими счетами. Переводы не считаются доходом или расходом, поэтому «Результат месяца» показывает движение денег за период, а «Текущий остаток» — сумму операций по счёту.

Операции можно привязывать к счёту без даты начала. Будущие операции не входят в текущий остаток до наступления их даты. Эквивалент остатка в рублях рассчитывается по курсу ЦБ на сегодня; для RUB курс равен 1. Курс операции при этом сохраняется на дату самой операции.

Старые операции, созданные до перехода на счета, сохраняются в истории, но не меняют текущие остатки. Экран показывает только созданные счета; новые добавляются кнопкой «Добавить счёт», а неиспользуемые можно удалить. Валюту счёта с привязанными операциями изменить нельзя: для другой валюты нужно создать новый счёт.

## Мобильные операции через Syncthing

При запуске приложение проверяет `mobile-sync/incoming` каждые пять секунд. Каждая операция передаётся отдельным JSON-файлом; после импорта приложение создаёт квитанцию в `mobile-sync/receipts`. Повторная доставка того же ID не создаёт дубликат в Excel.

После подтверждённого импорта входной JSON удаляется, а Syncthing переносит удаление на телефон. Ошибочные файлы сохраняются для повторной обработки; квитанции по умолчанию очищаются через 30 дней.

Путь папки задаётся в `local-data/finance.config.json`. Пример необязательных параметров находится в `finance.config.example.json`; при необходимости скопируйте файл в `local-data/finance.config.json` и измените папку синхронизации или срок хранения квитанций.

Для пробного ввода с телефона подготовлен локальный плагин [Finance Capture](obsidian-plugin/finance-capture/README.md) для Obsidian Mobile.

Плагин умеет вставлять форму прямо в любую заметку и создаёт read-only Markdown-карточку с читаемым именем для каждой мобильной операции. Имена начинаются с `1 — В очереди` или `2 — Архив`, поэтому ожидающие операции сортируются выше импортированных; после исчезновения синхронизированного JSON статус в имени обновляется автоматически. Пока операция ожидает импорта, удаление карточки также удаляет её JSON из очереди. Отдельная встраиваемая панель позволяет очищать архивные карточки или все мобильные записи.

Справочники Excel и активные счета автоматически экспортируются в `mobile-sync/config/lists.json` и через Syncthing используются плагином: добавление, изменение или удаление счёта сразу обновляет мобильный список и не требует новой сборки плагина. У каждой категории есть редактируемый эмодзи; он показывается в desktop-интерфейсе, мобильной форме и именах карточек.

На экране «Справочники» значения можно добавлять, переименовывать и удалять прямо в desktop-приложении. Изменения записываются в лист «Списки», расширяют диапазоны выпадающих списков Excel и создают бэкап. RUB, а также хотя бы одна категория дохода и расхода, обязательны; системные типы «Доход/Расход/Перевод/Инвестиция» защищены от редактирования.

«Инвестиция» создаётся только в desktop-форме. Она учитывается как расход обычного счёта и отдельным положительным движением капитала накопительного счёта. Для разных валют суммы списания и зачисления задаются вручную; для одной валюты они равны. Курс хранится только для рублёвой оценки расхода и не рассчитывает сумму зачисления. Категория зависит от типа накопительного счёта: «Вклад» или «Отложенные». Инвестиции и выводы из накоплений можно редактировать в истории операций: связанное движение капитала обновляется атомарно вместе с записью, а тип операции остаётся неизменным. Их также можно удалить вместе со связанным движением.

Новые операции содержат одно текстовое поле «Заметка». Отдельные описание и способ оплаты больше не используются: конкретное место хранения денег определяется выбранным счётом.

Экран «Настройки» содержит только системную информацию и действия: открытие папок Excel, бэкапов и Syncthing, ручное обновление мобильной конфигурации и восстановление выбранного бэкапа с подтверждением. Перед восстановлением приложение отдельно сохраняет текущее состояние книги. Справочники и счета остаются на своих экранах.

Текущий экран хранится в адресе (`#overview`, `#operations`, `#balance`, `#lists`, `#settings`) и сохраняется после перезагрузки. В боковой панели работают стрелки, Home/End и Enter; в таблицах стрелки перемещают фокус между строками, а Enter открывает операцию или переводит фокус в название счёта.

Excel-книга расширяется автоматически: когда свободными остаются менее 100 строк операций, приложение добавляет ещё 100 и обновляет связанные формулы и диапазоны.

## Тестирование

- `npm run test:api` — интеграционные тесты Excel и API;
- `npm run test:plugin` — тесты мобильного Obsidian-плагина;
- `npm run test:storage` — аварийная запись, восстановление, конкурирующие процессы, занятость файла и штатная остановка;
- `npm run test:e2e` — браузерные сценарии Playwright;
- `npm run qa` — синтаксическая проверка и все тесты.

API и браузерные тесты создают синтетическую Excel-книгу из `tests/create-fixture.mjs` с отдельными бэкапами, очередью и кэшем. Личные данные рабочей книги не используются для заполнения тестов; API-проверка дополнительно сверяет её контрольную сумму. Календарная дата тестов закреплена в `tests/test-clock.mjs`. При первом запуске браузерных тестов может потребоваться `npx playwright install chromium`.


## Защита идентичностей и сброс

Удаление импортированной операции не разрешает импорт того же ID повторно.
Реестр хранится внутри Excel и сохраняется при сбросе/восстановлении.
Обычные счета получают непереиспользуемые ID 5–104 (100 за срок жизни книги).
«Удалить историю» сохраняет оба вида счетов и начальный капитал; «Полная очистка»
удаляет их тоже. Справочники и резервные копии сохраняются в обоих режимах.

Перед первым запуском обновлённого сервера завершите старую очередь и сохраните
бэкап: ранее удалённые до внедрения реестра ID восстановить невозможно.
Плагин 0.10.2 совместим, переустановка для этого изменения не требуется.
При восстановлении события до времени восстановления отбрасываются; если текущий
реестр не читается, импорт блокируется с сохранением очереди.

API и браузерные сценарии получают собственные временные книги и серверы.
`FINANCE_TEST_REVERSE=1` меняет порядок сценариев; `FINANCE_TEST_INSTANT` задаёт
контролируемую дату. Возраст файлов в API-тестах согласован с тестовыми часами.

## Эксплуатация после аудита

Проверенное окружение: Node.js 24.15.0, Windows, один писатель на локальном диске.
Установка зависимостей — `npm ci`; полный контроль — `npm run qa`; аудит зависимостей — `npm audit`.

`npm run staging:mobile` запускает отдельную синтетическую книгу для проверки
телефона; `npm run recovery -- export "ПУТЬ"` создаёт проверяемый архив;
`npm run source:bundle` готовит исходники без рабочей книги и локальных настроек.
Автоматические тесты не заменяют проверку телефона и копии на другом физическом диске.
